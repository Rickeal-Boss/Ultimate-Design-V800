## 一、先回答「为什么上一轮的根本性修复看着没用」

主理人本波逐字节核验，**部署没有滞留**：

| 检验 | 方法 | 结果 |
|---|---|---|
| 远端 main 是否含 R74–R79 | `GET /commits/main` | `c0c902a`（R79 交接文档），与本地 HEAD 一致 |
| CI 是否跑过 R74–R79 | `GET /actions/runs?per_page=20` | R74…R79 每一个 commit 都有 run，**全部 success** |
| 线上包是否为新代码 | 拉 `main-*.js` + `R7Adapter-*.js` 反查特征串 | 含 `applyVisibility` / `cabinHidable` / `r71r7rear` ⇒ 确为 R74+ 产物 |
| 线上 HTML 缓存 | `Cache-Control: max-age=600`，无 Service Worker | 10 分钟即过期，非缓存假象 |

⇒ **结论：R74–R79 的代码确实在线，是处方靶点错了**，不是没上线：

- R76/R77/R79 削的是**程序化内饰顶棚**（headliner / starlight 的 y、z）。
- 用户截图里的「黑亮弧形面板 + 上方锯齿白边」是**外部壳 bodyMesh 的车顶内壁**——cabin 态 bodyMesh
  走 `DoubleSide`，车顶内壁直接露在星顶盖板之上；锯齿是 body GLB 车顶开口的非流形边界。
- **V800 从来没有车顶内壁剔除**（R74 注释原文「V800 无 roofCull 留空段」，只有 R7 有 R50 的机制）
  ⇒ 内饰件再怎么削，上面那层外壳车顶永远在。

本波把 R7 的 `buildRoofCulledIndex` 抽成共享纯模块并接到 V800，这才是那一块的正解。
