## 1. `clearcoatRoughness 0.06` + `RoomEnvironment` 硬边发光面 = 高光造型线的伪缺陷（**本轮最重要**）

**现象**：尾门折线在像素域量出相邻 6px 亮度极差 ΔL **195~211**（真车钣金线应 ≤100），
观感像"接缝/裂缝"。三轮几何调参全部无效：

| 版本 | 槽宽 | 槽深 | 峰值壁角 | 断面 | 结构式判据 ①②③ | 全摆幅 ΔL |
|---|---|---|---|---|---|---|
| b1b（尖 V + 硬边拆点）| 24/28mm | 3.0/3.5mm | 14.2° | 尖 V，行带拆点 | 黑缝 7px（不过）| **202** |
| R20-1c（smoothstep）| 44mm | 2.4/2.6mm | 10.3/11.2° | smoothstep | **①③ 过**（上 亮带7px/暗谷4px、下 亮带4px/暗谷8px）| **206** |
| R20-1d（平底 10mm + 直壁）| 52mm | 2.4/2.6mm | 6.86/7.50° | 平底 10mm + 直壁 + r6 | **FAIL**：下折线暗谷 15~21px（阈值 ≤10）、低机位亮带 21~30px（阈值 ≤12）| 未测（预期 ~200）|
| **R20-1e（定版）** = 1c 宽度 + 1d 壁形 | **44mm** | 2.4/2.6mm | **12.20/13.31%** | 平底 4mm + 直壁（无圆角）| 待测 | 待测 |

> **为什么最终回到 44mm**：1d 的"宽而浅"把下折线从窄深改成宽浅 ⇒ 暗谷反而被拉宽到 15~21px
> （① 无黑缝 ≤3px 与 ③ 亮带 ≤12px 是**反向权衡**）。1e 取「1c 的宽度 + 1d 的壁形」：
> 峰值斜率 18.2%→12.2%（壁形贡献），槽宽 52→44mm（暗谷收窄），两头的好处都要。
> 教训：**结构式判据是"带宽 + 对比度"二维的，单向往任一方向推都会撞另一条**。

**根因**：`paint-upper` 的 **`clearcoat 1.0` + `clearcoatRoughness 0.06`**（spec 原值，
适配层从未覆盖）≈ 镜面清漆，把 `RoomEnvironment` 里那几块**矩形发光板**原样镜像到车身。
槽壁上任何一小段法线扫过发光板的角度，整段就读成 **L=238 平顶高光**；**平顶边缘是贴图硬边**，
1~2px 硬跳，与曲面多光滑无关。

**判据含义**：壁角 −27%、槽宽 ×1.83 ⇒ ΔL +4（saturate）。**任何"调槽形压对比度"的路线都是死路。**

**修法（未落地，留给 look-dev）**：`clearcoatRoughness 0.06 → 0.14~0.22`（可选同时
`roughness 0.42 → 0.48`）。它模糊的是镜面 lobe，把发光板硬边糊成渐变。
代价：**全车 11 个 paint-upper 件一起从"镜面黑"降到"缎面黑"**，属设计取舍；
R10b 曾用 metalness 0.12 / roughness 0.42 / env 0.55 压"暖光大理石漩涡"，动 clearcoatRoughness
不碰底色漩涡，方向安全。A/B 需四机位 + 三种光照。

## 2. 通则：**几何可以是 C¹，环境贴图不是 C¹**

高光黑漆上的任何造型线，实际成像 = 曲面法线分布 × **环境辐照的连续性**。
本项目 env 是 `RoomEnvironment`（几块硬边发光矩形 + PMREM），其辐照场在矩形边界处**跳变**。
因此：

- 把曲面做到 C¹（甚至在 G² 意义上连续）**不能**消除"平顶高光 + 硬边"；
- 决定 ΔL 的是**辐照场的连续性**与**镜面 lobe 宽度（clearcoatRoughness / roughness）**，
  不是槽深、槽宽、壁角；
- 造型线的"可读性"来自**曲率突变**（κ 的阶跃），"对比度"来自**材质与光照**——
  这两个变量必须解耦调，混在一起调必然一轮一轮白跑。

推论：以后遇到"某件高光带硬边/双线/过曝"，先查 `clearcoatRoughness`、`roughness`、
envMapIntensity、env 来源的 PMREM 平滑度，**再**看几何。

## 3. `steps:1` 会让形变声明彻底失效（crown 必须配 `steps ≥ 2`）

`ExtrudeGeometry` 的 `steps` 决定**沿挤出深度有几圈环**。工厂默认 `steps: 1` ⇒ 深度方向只有
两端两圈顶点 ⇒ 任何"沿深度变化"的形变（本轮 `shaping.crown`）**没有任何顶点可作用**。

实测：首版给 4 坐垫只写 `shaping.crown`，`mid − end = 0.00mm`（纯 no-op）；补
`profile2D.steps = 8`（9 圈环）后立刻变成 **15.00mm**（端 +5mm、中点 +20mm），每垫 +280 tri。

**规则**：新增任何"沿挤出/沿 spine 变化"的形变字段时，必须同时确认分段数；
写进 spec 的形变若没有配套分段，等于没有声明。

### 3.1 ★ 形变的**极值点必须落成顶点**，否则 bbox 会漂（R20-1e 实测）
尾门 bbox 的 `zmin = 0` 只在 **u=0 且 t=0.5**（冠面最鼓点）的顶点上取得到。
把 `SEG_Y_COARSE` 从 14 改成 15（奇数）后没有任何站点落在 `t = 0.5`，
**bbox zmin 抬了 4.4µm**（世界 −2.835996 而不是 −2.836），直接破坏"bbox 逐位不变"的
贴花契约。修法：在站点表里**显式压入 `Y_MIN + HEIGHT/2`**，与粗分奇偶解耦（+92 tri）。

> 推论：任何"逐顶点取 min/max 当契约"的场合（bbox、包围球、贴花锚点），
> 曲面极值点必须是网格顶点；不能指望采样恰好覆盖。

### 3.2 ★ 圆角的弧长 = `R·sinθ`，由**转角**决定，不是由半径决定
R20-1d 想用"r6 圆角"摊开镜面反射带，实测：壁角只有 6.9~7.5° ⇒ 圆角水平跨度
**a = 0.705 / 0.765 mm**、垂直落差 **41.5 / 48.9 µm**，肉眼不可见，**撑不开反射带**。
转角小的地方，加大半径不会增加弧长（R→∞ 才趋近 R·θ）。

> 推论：**峰值斜率由"壁形"决定**（直壁恒定 = 平均斜率；smoothstep 中点是平均的 1.5×），
> 不由宽度/半径决定。R20-1e 用「44mm 宽 + 直壁」把峰值从 18.2%/19.8% 压到 12.20%/13.31%
> （−34%），同时槽宽回到 44mm 收窄暗谷 —— 这才是"宽度与斜率解耦"的正确用法。

## 4. 倒角落地（清单 B）的两个必须修正

### 4.1 `sUnits` 分母必须用 `max(sx, sy)`，不能用 `min`
`bevel.size` 是 **shape 空间单值**，而 shape 被 `(sx, sy)` **非等比**缩放，
一个 size 只能保证"某一个轴上是 r"。用 `min` 时，长轴世界半径被放大 `(max/min)` 倍：

| 件 | scale | `min` 方案 size | 世界内缩 x | `max` 方案 size | 世界内缩 x / y |
|---|---|---|---|---|---|
| `bumper-chrome-lip` | 1.86 / 0.04 / 0.05 | 0.2 | **372 mm** | 0.004301 | **8.00 / 0.17 mm** |
| `hood-panel` | 1.3 / 0.035 / 0.95 | 0.2 | **260 mm** | 0.005385 | **7.00 / 0.19 mm** |

即原式会把饰条两端各削掉三分之一长度。改 `max` 后两轴世界半径都 ≤ r（保守方向），
与"世界米制半径"的语义一致。`tUnits = r / sz` 不变。

### 4.2 轮廓适配闸门：`2·size / 轮廓最小边 > 50%` 一律跳过
倒角半径超过轮廓自身尺寸的一半时端面会自交/塌陷。命中：
`roof-panel`（`2s/H = 0.92`，顶冠边会直接消失）、`lantern-core-l/r`（0.51）。
**这不是"倒角重了"，是把形体删了。**

其余跳过规则：`primitive != extrude`、`edgeTreatment.type ∉ {rounded, bevel}`、
`bevelRadius ≤ 0`、已有 `profile2D.bevel`（不覆盖）、`tUnits ≥ 0.35·depth`（front-end
r=0.18/depth=0.08、taillamp-l 0.035/0.03 这类本来就没法倒）、`depth − 2t ≤ 0.02`。

### 4.3 倒角的语义与契约
`offset = −size` ⇒ **中段保持原轮廓、只内缩两端端面** ⇒ 整车/关键件 bbox **逐位不变**
（实测车长/宽/高、`body-lower` 三轴+顶高+尾面、四轮 pivot 12 个分量 **Δ=0.00mm**）。
`segments` 一律 2（控面数）。

## 5. `build_spec.py` 从 R6 起**不是全量真源**（裸跑会毁车）

- `build_spec.py` 最后改动停在 **R0**：产出 **125 个组件**，SEATS 还是 `box`、tailgate 还是 `box`；
  当前 spec 有 **185 个组件**。R6..R19 的几何精化是 `tools/a1_r3_roundness.py`、
  `tools/r12*_surgery.py`、`tools/r1x_apply.py` 这类**外科脚本直接改 JSON** 补进去的。
- 实测裸跑后果：**删掉 70 个组件** + **89 个组件 primitive 回退**（box ← extrude）。
- 原文件 `WRK = Path(r"<workspace>/.img2threejs")` 是**占位符**，原样跑直接 FileNotFoundError ——
  说明历史各轮跑的都是改过路径的临时副本。

**现行做法（三道保险，已落地）**：
1. **前置硬护栏**：非 `--r20-*` 模式且目标 spec 组件数 > 150 → 打印拒绝理由 + `sys.exit(2)`
   （确需重建 R0 基座须显式 `--force-full-rebuild`）。
2. **diff 白名单自检**：pass 跑完逐路径比对，只允许 `profile2D.bevel` /
   `profile2D.steps` / `profile2D.shaping.crown` / `curveSweep.crown`；越界即**回滚原文 + exit 3**。
3. **写盘 `newline="\n"`**：spec 是纯 LF（46k+ 行），Windows 默认文本模式会写 CRLF ⇒ 一次
   4.6 万行假 diff。

入口：`python build_spec.py --r20-a`（crown）/ `--r20-b`（bevel）/ `--r20-pass`（两者）。
三个 pass 均**幂等**（重跑 0 改动）。

## 6. 陈旧 bundle 会伪造历史基线（一次真实误报）

`.qa/factory_bundle.mjs` 是 **10-19 23:48** 的快照，比 `HEAD`（10-20 02:50）还老，
里面装着 **R19 之前**的工厂。任何 `import .qa/factory_bundle.mjs` 的脚本
（`run-bbox.mjs` / `distinctz.mjs` / `occluders.mjs` / `probe-bbox.mjs`）在重产后**静默返回旧几何**，
"验证通过"是假的。

实际后果：一次复核把 `body-lower` 量出 **y_max 1.090 → 1.660（+570mm）**、tri 1228 → 1340，
看着像"车身壳体长高"，其实是"R19 之前的车 vs 今天的车"。真值 HEAD 就已经是 1.660/1340。

**现行做法**：度量脚本**直接导入源码**，不经 bundle：
```bash
node --experimental-strip-types .qa/r20dev/measure.ts   # 尾门 bbox/tri/剖面/distinctZ
```
历史基线用 `git show HEAD:src/model/createV800Model.ts > /tmp/base.ts` 再直导。
（`--experimental-strip-types` 实测可吃 1.7 MB 的工厂 TS，376 节点全建。）

本轮数字漂移记录：旧 bundle 报整车 **57,916**，真值 **58,028**（少 112）。
