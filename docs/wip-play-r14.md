## 2. 实现位置与语义

### 2.1 `VehicleState` 新增三字段（`src/physics/Vehicle.ts`）

| 字段 | 语义 |
|---|---|
| `thermalHold: number` | 剩余锁定秒数；`>0` = 机械制动力被切断 |
| `thermalLocks: number` | 本局累计触发次数（诊断 / 测试） |
| `thermalArmed: boolean` | 迟滞布防位；初值 `true` |

`createVehicleState()` 一并初始化，`StateMachine.start()` 重建 state → 天然复位，无需改状态机。

### 2.2 `stepVehicle` 内的集中处理（保持纯函数）

顺序（`powerCut` 分支）：

1. **冗余优先**：`redundancyDecel > 0` → `thermalHold = 0`、`thermalArmed = true`（独立液压回路 + `heatless`，不为已判负的局再叠一层 2s 断力）；
2. **判定本步是否受锁** `thermalLocked = thermalHold > 0`，再倒计时 `thermalHold = max(0, hold - dt)`
   —— 先判后减保证切断步数 = `2/dt` = 240 步（±1 步浮点尾）；
3. `mechDecel = thermalLocked ? 0 : min(demand, μg)`；
   **`mechDecelDemand` 照记驾驶员需求**（HUD 才能说「你踩了但没力」，诊断也不失真）；
4. **回收保留**：`regen = min(regenReq, μg − mechDecel)`；锁定期 `mech=0` → 回收回到满值 1.47 m/s²（0.15g）。理由：电机回收不产生摩擦热、与液压热保护无关；2s 内完全断力会让 135 km/h 的车几乎不减速（只剩 0.7 m/s² 风阻滚阻），惩罚过度且不可控；
5. **加热门控** `mechDecel > 0.5 && !heatless` → 锁定期 `mech=0` 自动转降温；
6. **触发 / 重布防**（仅驾驶员路径）：
   - `thermalArmed && brakeTemp >= thermalTriggerTemp` → `thermalHold = 2`、`armed = false`、`locks++`；
   - `!thermalArmed && brakeTemp < thermalRearmTemp` → `armed = true`；
7. 之后才是 `overheat` / `eff` / `accel` 合成 —— 触发发生在**施加力之后**，触发那一步仍算满力（不吞掉已发生的制动）。

加速段（`powerCut=false`）：`thermalHold = 0`，温度按 `coolRate` 降，低于 `rearm` 时重新布防。

### 2.3 `brakeTempEfficiency` 为何「保留但几乎不可见」

`thermalHold` 把 `mech` 直接归零，是 ×0.85 衰减的**严格超集**；且 `coolRate=0.5` 让 2s 锁定期把温标从 1.0 清到 0，所以玩家能观察到 `1.0 < T` 的窗口只有「越线那一步」（≈8.3ms，距离差 <0.01m）。

- 代码路径与常量**完整保留**（越线步、以及任何外部写入 `brakeTemp>1` 的场景如调试/白盒测试仍生效，测试 ③ 的白盒段就验证了「过热 + 已解锁」时仍按 ×0.85 出力）；
- 不做「先衰减 0.85 再断力」的双重惩罚：物理上是同一套热失效，双罚会让玩家觉得莫名其妙；
- 若主理人希望衰减可见，唯一办法是把 `thermalTriggerTemp` 抬到 1.2~1.3（红区上移），代价见 §3.4 取舍表。

2. `redundancy.test.ts`「断裂的惩罚真实存在：用时 >2.5×、距离 >2.5×」→ 改为 **>2.2× / >1.8×，并加绝对差 ≥8 s / ≥150 m**。

## 7. 遗留风险

1. **每局必吃一次 2s 断力**：v0=200 下单次满刹的机械摩擦功 ≈1.6~1.9 温标，只要 b≥0.6 就必然越过 1.0。因此 0.86~0.97 的停时被压成平台（7.31 s），深踩的技术收益只剩「早 0.04 s 触发」。若主理人认为「必答桥段」抢了操作感，唯一解法是把 `thermalTriggerTemp` 抬到 1.2~1.3（红区上移、断力点落在 ~90 km/h），代价是 §3.1 的表格要整体重标、且 `brakeTempEfficiency` 的衰减窗口变可见（正面）。**本轮按用户「42% 处触发」的原始描述取 1.0。**
2. **得分天花板下移 38%**（8908 → 5487）：`calcScore` 未改，是停时变长的直接结果。若排行榜/最佳成绩有历史数据，会出现「老纪录再也打不破 / 新纪录普遍更低」，建议主理人决定是否清榜或加版本号。
3. **HUD 只做了静态审查**：CSS 自注入 + 类切换通过 `tsc` 与代码走查，未做真机/无头截图目检（perf 子代理正在跑页面，避免抢占）。首帧观感（红条与倒计时位置、与 toast/冗余徽标的遮挡）需要一次目检。
4. **距离口径的 1.1 m 倒挂**（0.86→0.97）：时间严格不增，距离 +0.5%。若后续有人加「距离越短越好」的断言需要先看 §3.5。
5. `thermalHold` 在 `powerCut=false` 时被直接清零：本作不可能在刹车段中途松刹车（状态机单向），若不改状态机新增「放弃刹车」分支，此语义安全；一旦新增回退到 accel 的分支，锁定会被静默取消。
